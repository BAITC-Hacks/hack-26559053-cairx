# Career Quest — правила проекта

## Задача

Внутренняя HR-платформа: сотрудник видит профиль, разрывы по навыкам
до следующего грейда и 1–3 рекомендованные активности с объяснением.
HR видит срез по проседающим компетенциям.
Ядро проекта — качество и объяснимость рекомендации, а не интерфейс.

## Стек

- Python 3.12, FastAPI, Uvicorn, Pydantic v2
- Фронт: static/index.html + Tailwind и DaisyUI через CDN + vanilla JS,
  отдаётся тем же FastAPI
- Данные: JSON и CSV из data/, грузятся в память при старте. БД нет
- Запуск: docker compose up

## Структура

app/main.py — роуты, mount статики
app/schemas.py — Pydantic-модели
app/services/loader.py — загрузка датасета, upload, reset
app/services/scoring.py — детерминированный скоринг рекомендаций
app/services/explain.py — обоснование через LLM + fallback
static/ — интерфейс
data/ — стартовый кит

## Главное правило рекомендаций

Скоринг считается в Python детерминированно и опирается минимум
на четыре фактора:

1. разрыв: текущий уровень навыка против требуемого для следующего грейда
2. критичность навыка именно для следующего грейда, а не абсолютный минимум
3. история участия: пропуски и отказы по похожим активностям понижают вес
4. достижимость: gain активности и max_level навыка

LLM только формулирует текст объяснения из уже посчитанных чисел.
Если LLM недоступен — отдаём шаблонную фразу из тех же чисел
и ставим llm_used: false. Рекомендация обязана работать без LLM.

Рекомендация по одному полю профиля запрещена условиями задачи.
Каждый ответ /api/recommend возвращает объект factors с числами,
на которых построено решение.

## Запреты

- Никакого React, Vue, npm, сборщиков
- Никакой БД, миграций, логина, JWT, регистрации
- Никаких моков, заглушек и захардкоженных ответов вместо реальной логики
- Никаких публичных рейтингов сотрудников по результативности
- Никаких баллов за обязательные процессы
- Секреты только через переменные окружения, .env в репо не коммитим

## Обязательно

- Валидация входа через Pydantic
- Глобальный обработчик ошибок, понятный JSON вместо стектрейса
- .env.example со всеми переменными и комментариями
- Детерминизм: один и тот же профиль даёт один и тот же порядок
  рекомендаций, temperature=0, стабильная сортировка
- Загрузка дополнительных профилей и истории в формате датасета
  через /api/upload — на защите жюри грузит свои проверочные профили
- Отклик интерфейса до 2 секунд, рекомендация до 10 секунд
- После каждой законченной части обновлять README
- Маленькие частые коммиты с осмысленными сообщениями
